# Smart Log Analyzer

An AI-powered log observability platform built with FastAPI, PostgreSQL, SQLAlchemy, and vanilla JavaScript.

The application provides real-time and historical log analysis with advanced analytics features such as anomaly detection, clustering, semantic search, alert management, and interactive dashboards.

---

## Project Overview

Smart Log Analyzer is an AI-powered log observability platform designed to help engineers monitor, investigate, and analyze application logs from both real-time systems and historical datasets.

Modern applications generate thousands of logs every minute. Manually inspecting these logs becomes difficult as systems scale. This project addresses that problem by providing a centralized platform where logs can be ingested, stored, filtered, analyzed, clustered, searched semantically, and monitored for anomalies.

The platform supports two different ingestion workflows:

* **Realtime Logs** – logs generated by running applications and ingested through API endpoints.
* **Uploaded Logs** – historical log files uploaded for offline analysis without affecting live monitoring data.

Once logs are stored, the analytics engine provides timeline analysis, anomaly detection, service-level health monitoring, clustering of similar logs, semantic search, and alert generation.

The goal of this project is to demonstrate backend engineering, asynchronous APIs, database design, analytics pipelines, machine learning integration, and frontend dashboard development in a single production-style application.

## How the System Works

The platform follows a layered architecture.

1. Applications send logs through ingestion APIs or users upload historical log files.
2. Logs are normalized and validated by the ingestion layer.
3. Validated logs are stored in PostgreSQL with an ingestion mode indicating whether they belong to realtime or uploaded datasets.
4. Analytics services query the stored logs and generate insights such as:

   * Timeline aggregations
   * Service health metrics
   * Anomaly detection
   * Log clustering
   * Semantic similarity search
5. Alert services continuously evaluate log patterns and generate alerts when thresholds or anomalies are detected.
6. FastAPI exposes all functionality through REST APIs.
7. The frontend consumes these APIs and renders dashboards, analytics views, alert pages, and log exploration tools.

## Machine Learning Components

### Log Clustering

The clustering engine groups structurally similar log messages using TF-IDF vectorization and K-Means clustering. This helps identify recurring failure patterns and reduces manual investigation effort.

### Semantic Search

Semantic search converts log messages into vector representations and retrieves the most similar logs using cosine similarity. This enables engineers to search by meaning rather than exact keywords.

### Anomaly Detection

The anomaly engine analyzes timeline activity and identifies unusual spikes in log volume that may indicate incidents, outages, deployment issues, or abnormal application behavior.

## Database Migrations

Alembic is used to manage database schema changes.

### Generate Migration

```bash
alembic revision --autogenerate -m "migration description"
```

**Important**

After generating a migration, review the generated file inside the `alembic/versions` directory and verify that all tables, columns, relationships, indexes, and constraints are correctly detected.

If Alembic misses any changes, add them manually before applying the migration.

### Apply Migration

```bash
alembic upgrade head
```

This command applies all pending migrations and updates the database schema.

Create a new migration only when the database schema changes, such as:

- Adding a table
- Adding a column
- Modifying relationships
- Adding constraints
- Updating indexes
